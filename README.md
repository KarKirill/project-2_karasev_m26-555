# Примитивная база данных

Консольное приложение на **Python 3.12** для управления таблицами и записями. Проект создан с помощью **uv** и использует JSON-файлы для хранения метаданных и данных таблиц.

Программа поддерживает создание и удаление таблиц, полный набор **CRUD-операций** (добавление, чтение, обновление и удаление записей), фильтрацию по условию `WHERE` и отображение результатов с помощью **PrettyTable**. Для повышения удобства и надёжности используются декораторы обработки ошибок, подтверждения опасных действий и измерения времени, а также кэширование SELECT-запросов.

## Возможности

- Создание таблиц со столбцами типов `int`, `str`, `bool`.
- Автоматическое добавление столбца `ID:int` и генерация ID при добавлении записей.
- Просмотр списка таблиц и сведений о конкретной таблице.
- Добавление записей с проверкой количества значений и их типов.
- Чтение всех записей или выборка по условию `WHERE`.
- Обновление записей через `UPDATE ... SET ... WHERE ...`.
- Удаление записей через `DELETE ... WHERE ...`.
- Подтверждение удаления записей и таблиц через `y/n`.
- Измерение времени выполнения пользовательских команд `INSERT` и `SELECT`.
- Кэширование повторных `SELECT` с автоматической очисткой кэша при изменении данных.
- Сохранение структуры таблиц и записей между запусками программы.
- Обработка ошибочных команд и некорректных пользовательских значений без завершения программы.

## Требования

- Python 3.12 (при необходимости `uv` может установить подходящую версию Python);
- [uv](https://docs.astral.sh/uv/getting-started/installation/);
- Git - для клонирования репозитория.

Основные зависимости: **prompt** (консольный ввод), **prettytable** (вывод таблиц). Для разработки используется **Ruff**.

## Управление таблицами

| Команда | Назначение |
| --- | --- |
| `create_table <имя> <столбец:тип> ...` | Создать таблицу |
| `list_tables` | Показать список таблиц |
| `drop_table <имя>` | Удалить таблицу и её JSON-файл после подтверждения |
| `info <имя>` | Показать структуру и количество записей |
| `help` | Показать справку |
| `exit` | Завершить программу |

Поддерживаются типы **`int`**, **`str`** и **`bool`**. Столбец `ID:int` создаётся автоматически, поэтому указывать его в `create_table` или передавать значение ID в `insert` не нужно. Имена столбцов должны быть уникальными.

Пример создания таблицы:

```text
Введите команду: create_table users name:str age:int is_active:bool
Таблица "users" успешно создана со столбцами: ID:int, name:str, age:int, is_active:bool

Введите команду: list_tables
- users
```

## CRUD-операции

| Операция | Синтаксис |
| --- | --- |
| **INSERT** | `insert into <таблица> values (<значение1>, <значение2>, ...)` |
| **SELECT** | `select from <таблица>` |
| **SELECT WHERE** | `select from <таблица> where <столбец> = <значение>` |
| **UPDATE** | `update <таблица> set <столбец> = <значение> where <столбец> = <значение>` |
| **DELETE** | `delete from <таблица> where <столбец> = <значение>` |

Правила ввода значений:

- Строки (`str`) записываются **в двойных кавычках**, например `"Sergei"`.
- Целые числа (`int`) передаются без кавычек: `28`.
- Логические значения (`bool`) записываются как `true` или `false`.
- При добавлении записи нужно передать значения **для всех столбцов, кроме ID**.
- `UPDATE` и `DELETE` требуют условие `WHERE`; `UPDATE` не позволяет менять `ID`.
- Если условию соответствуют несколько записей, обновляются или удаляются все найденные записи.
- Перед `DELETE` и `DROP TABLE` программа обязательно запрашивает подтверждение.

## Декораторы и замыкание

Реализация находится в `src/primitive_db/decorators.py`; подключение к пользовательским командам - в `engine.py`.

| Компонент | Назначение | Где применяется |
| --- | --- | --- |
| `handle_db_errors` | Перехватывает ошибки и выводит понятное сообщение | Обработка пользовательской команды |
| `confirm_action(action_name)` | Запрашивает подтверждение `y/n` перед изменением данных | Удаление записей и таблиц |
| `log_time` | Измеряет длительность операции с помощью `time.monotonic()` | `execute_insert()` и `execute_select()` |
| `create_cacher()` | Создаёт декоратор с кэшем в замыкании | Получение записей для SELECT |

### Подтверждение удаления

При ответе `n` удаление отменяется, данные не меняются. При ответе `y` операция выполняется. Любой другой ответ приводит к повторному запросу `y/n`.

```text
Введите команду: delete from users where ID = 2
Подтвердите действие "удалить записи" [y/n]: n
Операция отменена.

Введите команду: drop_table users
Подтвердите действие "удалить таблицу" [y/n]: n
Операция отменена.
```

Если `DELETE` не находит записей по условию `WHERE`, программа сообщает об этом без запроса подтверждения.

### Измерение времени

После команд `INSERT` и `SELECT` выводится длительность их выполнения:

```text
Время выполнения execute_insert: 0.016000 с
Время выполнения execute_select: 0.000000 с
```

Значение зависит от компьютера, объёма данных и разрешения системного таймера. Для очень быстрых операций время иногда отображается как `0.000000 с`. Время выводится также при ошибке выполнения этих команд.

### Кэширование SELECT

Функция `create_cacher()` создаёт **замыкание**: словарь с результатами запросов сохраняется между вызовами декорированной функции.

- **Первый SELECT:** данные читаются из JSON, результат фильтрации сохраняется в кэше.
- **Повторный SELECT** с тем же именем таблицы и условием `WHERE`: возвращается сохранённый результат, без повторного чтения JSON.
- **Другой WHERE:** создаётся отдельная запись кэша.
- **После успешных INSERT, UPDATE, DELETE или DROP TABLE:** кэш очищается, чтобы следующий SELECT получил актуальные данные.
- **При отмене удаления (`n`):** кэш не очищается, поскольку данные не изменились.

Кэш действует **только во время текущего запуска приложения** и не сохраняется на диск. Результаты копируются с помощью `deepcopy()`, чтобы изменения возвращённых словарей не затронули содержимое кэша.

### Обработка ошибок

Программа проверяет существование таблиц, названия столбцов, типы значений и корректность синтаксиса. Декоратор `handle_db_errors` перехватывает типичные ошибки, выводит сообщение и позволяет приложению продолжать принимать команды. Например:

```text
Введите команду: create_table products price:float
Некорректное значение: float. Попробуйте снова.

Введите команду: select from missing
Время выполнения execute_select: 0.000000 с
Ошибка: Таблица "missing" не существует.
```

## Хранение данных

**`db_meta.json`** содержит схемы таблиц. Пример:

```json
{
    "users": {
        "ID": "int",
        "name": "str",
        "age": "int",
        "is_active": "bool"
    }
}
```

Записи хранятся отдельно, по одному JSON-файлу на таблицу, например **`data/users.json`**:

```json
[
    {
        "ID": 1,
        "name": "Anna",
        "age": 26,
        "is_active": true
    }
]
```

После успешных изменений данные сохраняются на диск. При удалении таблицы удаляются её метаданные и файл с записями. Файлы `db_meta.json` и каталог `data/` исключены из Git через `.gitignore`.
